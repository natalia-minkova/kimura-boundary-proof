# Source provenance and IP review

## Phase 0 source

The implementation reviewed for this first local commit is `boundary_proof/__init__.py`, `boundary_proof/__main__.py`, `boundary_proof/chain.py`, `mutation_check.py`, and `tests/test_chain.py`. The JSON files in `examples/` were generated by this implementation. The project records these as original Phase 0 work attributed to Natalia Minkova, trading as Cyber Kimura, and places that work under Apache-2.0.

## Prior Kimura work

Existing Kimura research supplied general ideas: authority lineage and replay checks (A02 synthetic robot), execution-time enforcement and independently observed state (AAT), paired guarded and positive checks (Exact Retest and Authority Breaker), disposable mutation testing (Agent Mutation), and local hash-chained evidence with stated provenance limits (Proof Capsules). These are design patterns and problem statements, not copied source code.

For this review, the local `kimura-mut-uas-physical` source tree was inspected, including `kimura_assessment/boundary_proof.py` and `kimura_assessment/aat/core.py`. The former defines a different protocol of contracts, test pairs, and capsules; the latter has its own event digest and journal. Source searches across the available local Kimura trees found no Phase 0 implementation classes (`AuthorizationService`, `ActionEndpoint`, `AgentController`, `ReferenceChain`) or distinctive Phase 0 mutation anchors, race assertions, and evidence-profile strings in those trees. A comparison of the six Phase 0 Python files against 724 Python files in `kimura-mut-uas-physical` found one eight-line match, a run of standard-library imports in `mutation_check.py` and `kimura_assessment/impact_twin_backends.py` (also present in a duplicate proof tree). This is ordinary import boilerplate, not reused implementation logic. Common operations such as sorted-key JSON and SHA-256 appear in both projects, but their small expressions and schemas differ. No source, test fixture, schema, text, or binary from those repositories was identified as copied or adapted into this Phase 0 repository. The reuse inventory is therefore **none** for copyrightable implementation material.

Because no reused implementation was identified, there is no prior Kimura code to relicense in this commit. No ArduPilot or other GPL source fragment was identified. The direct import and dependency review is in `DEPENDENCIES.md`. Repository proximity and a shared owner name alone would not establish relicensing rights if copied material were later found.

## Review limits

The Phase 0 files had no prior Git history when reviewed, so this comparison cannot independently prove who typed every line or rule out an undiscovered source. The ownership attribution above reflects the project owner's statement and the available local evidence; it is not a legal opinion. Any later discovery of copied or third-party material requires a new file-level provenance and license review before distribution or relicensing of that material.
